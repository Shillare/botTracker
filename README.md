# gift_parser

Парсер Telegram-подарков: обходит рынок перепродажи через MTProto-аккаунты,
ищет новые лоты по заданным фильтрам и публикует их в форум-чат через бота.

## Как устроено

| Файл | Назначение |
|---|---|
| `main.py` | Основной парсер: обход каталога подарков, фильтры, рассылка, бронирование |
| `login.py` | Добавление MTProto-аккаунтов: логин по номеру и коду, автозапись в `accounts.json` |
| `accounts.json` | Список аккаунтов парсера (создаётся автоматически, **не** в репозитории) |
| `accounts.example.json` | Шаблон формата `accounts.json` |
| `xray_config.json` | Конфиг прокси (содержит UUID — **не** в репозитории) |

## Установка

```bash
python -m venv .venv
# Linux/macOS:  source .venv/bin/activate
# Windows:      .venv\Scripts\activate

pip install -r requirements.txt
```

## Настройка

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Впиши в `.env` токен бота и api-ключи. Файл в репозиторий не попадает.

## Запуск

```bash
python login.py      # добавить аккаунты парсера
python main.py       # запустить парсер
```

Работа через прокси (обязательно, если аккаунты заведены через прокси):

```bash
GIFT_PROXY=1 python main.py          # Linux/macOS
set GIFT_PROXY=1 && python main.py   # Windows
```

## Аккаунты

`login.py` работает в цикле: вводишь номер телефона — скрипт запрашивает код
из Telegram и **сам** дописывает запись в `accounts.json`. В коде `main.py`
ничего править не нужно.

```bash
python login.py
[добавлено: 0] Номер телефона или имя сессии (Enter/Ctrl+C — выход): +79042862664
  Номер +79042862664 -> сессия acc1
Please enter the code you received: 12345
  Готово: acc1 -> Ivan
  Записан в accounts.json
```

Чтобы завести аккаунт через конкретный порт прокси:

```bash
GIFT_PROXY=127.0.0.1:10810 python login.py
```

## Важно про IP

Telegram отзывает сессию при смене исходящего IP. Поэтому:

- аккаунт должен работать через **тот же** прокси, через который был заведён;
- в `accounts.json` за это отвечает поле `proxy_port`;
- для аккаунтов с `proxy_port` ротация прокси **отключена** — при падении
  прокси бот предупредит, но не переключит аккаунт на другой IP.

Один Telegram-аккаунт = одна сессия. Дублировать один номер в разные
`.session` нельзя: Telegram держит одну активную авторизацию, и лишние
сессии будут мешать друг другу.

## Защита от флуда

Каждый MTProto-запрос проходит через per-account лимитер (по умолчанию
2 запроса/сек), `FLOOD_WAIT` выдерживается ровно на столько, сколько просил
Telegram. Ключевые настройки — в начале `main.py`:

```python
RPS_PER_ACCOUNT = 2.0        # запросов в секунду на аккаунт
MIN_TYPE_INTERVAL = 40       # минимальный интервал между опросами типа, сек
POLL_SECONDS = 5             # пауза между циклами
SEND_RPS = 2.0               # сообщений в секунду боту
MAX_RESOLVE_PER_CYCLE = 300  # сколько продавцов досощать за цикл
```

Слишком частое опрашивание — причина разрыва сессий, а не сам Telegram.

## Что не должно попадать в репозиторий

В `.gitignore` добавлены `.env`, `*.session`, `xray_config.json`, логи и
базы состояния. Файлы `.session` — это **живые ключи авторизации**: тот,
у кого есть такой файл, может войти в аккаунт от твоего имени. Держи их
локально.
